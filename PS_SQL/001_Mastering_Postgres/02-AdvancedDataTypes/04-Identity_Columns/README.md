# 🆔 Lesson 4: Identity Columns in PostgreSQL

Introduced in PostgreSQL 10, **Identity Columns** (`GENERATED AS IDENTITY`) provide the standard SQL-compliant way to create auto-incrementing integer columns, replacing the legacy `SERIAL` pseudo-type.

---

## 1. Identity Columns vs. `SERIAL`

| Feature | `SERIAL` (Legacy) | `IDENTITY` Columns (Modern Standard) |
| :--- | :--- | :--- |
| **SQL Standard** | PostgreSQL Proprietary Shorthand | ANSI SQL Standard Compliant |
| **Manual Insert Prevention** | Does not prevent manual inserts by default | `GENERATED ALWAYS` strictly blocks manual inserts |
| **Permissions** | Requires separate permissions on sequence object | Sequence permission is attached directly to table |

---

## 2. Syntax Variations

### **1. `GENERATED ALWAYS AS IDENTITY` (Strict - Recommended)**
Blocks any attempt to insert a custom value into the column unless overridden:
```sql
CREATE TABLE employees (
    emp_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT
);

-- Fails! PostgreSQL rejects manual ID entry:
INSERT INTO employees (emp_id, name) VALUES (99, 'Alice'); 
-- ERROR: cannot insert into column "emp_id"

-- Allowed only with explicit override:
INSERT INTO employees (emp_id, name) OVERRIDING SYSTEM VALUE VALUES (99, 'Alice');
```

### **2. `GENERATED BY DEFAULT AS IDENTITY` (Flexible)**
Uses the auto-increment sequence unless a manual ID is explicitly provided:
```sql
CREATE TABLE products (
    product_id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title TEXT
);

-- Works! Auto-generates sequence number
INSERT INTO products (title) VALUES ('Laptop'); 

-- Works! Uses manual ID 500
INSERT INTO products (product_id, title) VALUES (500, 'Custom Item'); 
```
